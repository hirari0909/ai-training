# チケット処理プロンプト

## 依頼内容
- チケットの要件を確認し段階的に処理を行う

## step1. 設計の修正内容を出力
チケット要件に基づき、設計の修正計画・どこをどう直すのか？をレポートしてください。
修正計画を確認する事が目的です。プログラムソース側の確認・レポートは不要。
- 設計書は`Docシステム/外部設計`配下にある
- 結果レポートはMD形式で出力する
- レポートには修正ファイル・修正内容を記載すること
  `ticketwork/01_{修正タイトル}_設計修正計画.md`のようなファイル名で保存してください。
## step2. 設計書の修正内容
step1で出力した修正計画に基づき、設計書の修正を行ってください。
修正結果は同じくMD形式でレポートして下さい。
- 設計書の修正ルールは下記参照  
  `prompt/00.設計/設計_Executor.md`を参照してください。
- 修正内容は、修正前と修正後の差分を出力してください。
- step1で計画した内容と差分がある場合は注釈で補足してください
- 修正内容は、コードの差分形式で出力してください。
`ticketwork/02_{修正タイトル}_設計修正内容.md`のようなファイル名で保存してください。

## step3. コードの修正
step2のレポートmdと設計書の修正内容に基づき、コードを修正してください。
- コードの修正内容は、修正前と修正後の差分を出力してください。
- コードの修正内容は、コードの差分形式で出力してください。
- step2で計画した内容と差分がある場合は注釈で補足してください
- CDルールに従ってコードを修正してください。
    - `prompt/01.CD/CD_ルール.md`を参照してください。
    - `prompt/01.CD/CD_Executor.md`を参照してください。

## step4. 単体テストの実行
コードの修正が完了したら、レポートの内容から、単体テストクラスを作成・修正を実施して
単体テストを実行してください。
- 下記の単体テストの実行内容に沿った内容wを行ってください。
    - `prompt/02.UT1/単体テスト_Executor.md`を参照してください。
- コード修正内容のレポートを下記に添付します
`ticketwork/03_{修正タイトル}_CD単体テスト結果.md`のようなファイル名で保存してください。
