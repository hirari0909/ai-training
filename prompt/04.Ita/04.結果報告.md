# 結合テスト結果レポートを作成する

「01.ケース作成」のケース一覧と「03.テストの実施」の打鍵結果を集約し、**正常終了件数・障害件数・修正件数・障害概要・最終結果**をまとめた結合テスト結果レポートを作成する。

## 前提
- **対象**: `training-bookshelf`（書籍管理システム）
- 本ステップは打鍵を行わない。**既存の成果物を集約・突合してレポート化**する
- 障害修正の判断は「設計書を正」とする（ケース＝設計書由来）

---

## 1. 入力を集約する

| 用途 | パス |
|------|------|
| ケース母数の確定 | `Docsシステム/結合テスト/ケース/00_テストケース一覧.md` |
| 実施結果（OK/NG）| `Docsシステム/結合テスト/結果/00_テスト実施サマリ.md`、各 `SCxx_結果.md` |
| 障害の証跡 | `Docsシステム/結合テスト/結果/img/` のスクリーンショット |
| 修正内容（あれば）| 修正コミット／git履歴、修正レポート（`コード修正完了レポート.md` 等）|

### 集約手順
1. ケース一覧から**総ケース数**を確定する
2. 実施結果から **OK / NG / 未実施** を集計する（一覧の総数と実施結果の件数が一致することを検証。不一致は所見に記載）
3. NG（障害）を1件1行で台帳化する。各障害に**障害ID**（`BUG-001` …）を採番する
4. 各障害の対応状況を確認する: `修正済 / 未修正 / 対応不要(仕様)`、修正済は**再実施結果（再打鍵でOKか）**を突合
5. 最終判定を行う:
   - 全ケースOK（NG=0、または全NGが修正済かつ再実施OK）→ **合格（クリア）**
   - 未修正・再実施NGが残る → **条件付き合格／不合格**（残課題を明記）

---

## 3. 作成時の注意
- **数値の整合**: 総ケース数 ＝ OK＋NG＋未実施。シナリオ別合計と全体集計が一致すること。不一致は必ず所見に明記
- **障害の二重計上禁止**: 同一原因で複数ケースが落ちた場合は障害IDを1つに集約し、該当ケースを併記する
- **修正済の定義**: 「コード修正＋再打鍵でOK」を確認できたものだけを修正済とする。コード修正のみで未再実施は「未修正（要再実施）」扱い
- **証跡必須**: 障害詳細には修正前後のスクリーンショット（または該当`SCxx_結果.md`への参照）を必ず添付
- **クリア判定**: NG=0、もしくは全NGが「修正済（再実施OK）」または「対応不要（仕様・設計書と一致）」のときのみ**合格（クリア）**と結論する。それ以外は条件付き合格／不合格とし残課題を明示
- **設計書を正**: 実装と設計が異なる場合の障害判定は設計書基準。設計側の誤りは「残課題・申し送り」に分離して記載
